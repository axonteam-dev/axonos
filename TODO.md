# Текущие задачи AxonOS

- [ ] Постоянный дисковый корень и установка с GRUB для BIOS/UEFI. Драйвер ext2 пока не обеспечивает необходимые для apt операции (включая произвольное уменьшение truncate, triple-indirect блоки, удаление, переименование, синхронизацию параллельных операций); не считать установку готовой. На host реальный драйвер проверен на ext2-образах 1/4 КиБ: создание каталогов/файлов/symlink до размера блока, UID/GID выше 65535, chmod/chown inode, 400 КБ записи, увеличение truncate, truncate(0) до двойных косвенных блоков, повторное монтирование и e2fsck. Гостевые системные вызовы и случаи ошибок требуют дальнейшей проверки.
  - [ ] Исправить сохранение метаданных корневой ext2: QEMU BIOS, 3 ГиБ, 1 vCPU, отдельный MBR/ext2-образ, загрузка без initfs — тестовый shell с диска записал маркер, второй запуск прочитал его и записал второй; после принудительной остановки `e2fsck -fn` обнаружил неверные счётчики свободных блоков и inode в superblock. Нужны корректная отметка dirty, запись метаданных и аппаратный flush, а также полноценный тест штатного shutdown; наличие файлов не доказывает crash consistency.
    - Перед первой записью снимается `EXT2_VALID_FS`, на размонтировании без flush флаг остаётся снятым; QEMU и `dumpe2fs` подтвердили `not clean`. Это не обеспечивает порядок записи при внезапном отключении питания: flush ещё не реализован. Счётчики при принудительной остановке остаются неверными.
    - QEMU/KVM, 3 ГиБ, 1 vCPU: тестовый ext2 root без initfs монтировался и записывал файл на IDE PIO, SATA `ich9-ahci`, NVMe и `pvscsi`; это не проверка cache flush или полного установщика. QEMU `lsi53c895a` (1000:0012) не поддерживается. Реальные устройства и VMware не проверены.
    - [ ] Разобрать долгую/останавливающуюся полную распаковку `initfs.sfs` на ext2 (пользователь видит 22%). В отдельной QEMU VM при обработке полного образа два снимка CPU с интервалом 20 с попали в разные ATA PIO операции (outsw и status inb); это не доказывает причину зависания у пользователя. Убрано независимое ограничение записи каталога в 12 блоков, host-тесты роста каталогов с косвенными блоками и e2fsck прошли; полная распаковка и её скорость не подтверждены.
  - [ ] Исправить запуск PID 1 при 1 ГиБ: в QEMU с 1 vCPU heap выделил bootstrap exec stack по адресу 0x8f3afa0, ниже безопасного диапазона от 0x60000000; exec закономерно возвращает -3. При 3 ГиБ тестовый shell запускается. Нужно безопасное размещение стека, а не удаление проверки.
